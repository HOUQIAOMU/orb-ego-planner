# 相机位姿与 Current Frame 显示

用户要求：确认 ORB 到占据地图的定位链路，在占据窗口显示相机位置，并实时显示 RGB current-frame。沿用已授权的板端实施和同进程无 ROS 架构。

根因：rgbd_map.cpp 已将同帧 T_world_camera 交给 MappingWorker，DepthProjector 用它将深度转换到地图坐标。OccupancyDisplay 却只接收 MapReader，没有相机输入，当前三色轴只是固定原点。

这是现有显示入口的小改动。采用原 Pangolin 窗口中的相机视锥/坐标轴/XYZ 与 RGB 小窗，复用应用已经拥有的彩色帧；独立 OpenCV 窗口会多一个 GUI 事件循环，ROS/RViz 会引入当前不需要的依赖。此实现选择由代理根据现有工程决定。

显示输入为一份带捕获索引、接收时间、ORB 数字记录和 verified 标记的自有 BGR 图像；单槽邮箱保留最新帧，无显示历史队列，线程间不共享可变采集缓冲。RGB 在跟踪失效时仍更新并显示状态。三维相机使用完整 T_world_camera，光学轴右/下/前；只有位姿经过绑定验证、仍属于当前 ORB 来源、未过期且匹配所显示地图的来源和 epoch 才绘制。地图过期与相机位姿失效分别显示原因，不复用固定原点充当相机位置。地图重置时不连接旧坐标。

验收：独立测试图像所有权、最新帧替换、失效时保留 RGB、完整旋转/平移方向、来源/epoch/超时拒绝；工作站及 ARM 全套 CTest；真实录制序列显示回放截图，确认 RGB 颜色/朝向及非原点相机标记。保留原 ORB 核心和旧录制，不接规划，不宣称几何精度提高。
