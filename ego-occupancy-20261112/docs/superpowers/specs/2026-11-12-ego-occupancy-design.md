## 1. 已确认目标与范围

用户明确的新主线是 RK3576 + 单台 D435i + 已跑通的 ORB-SLAM3，为无人机穿过空心障碍物提供环境表示，之后接入去 ROS 的 EGO-Planner；控制器不在本次范围内。用户已确认建图和未来规划在同一个 C++ 进程中运行。以上明确需求优先于旧 AGENTS.md 中的 RTAB-Map 路线和阶段约定。

本阶段交付一个独立 C++ 占据地图库、离线验证入口和实时手持显示入口。完整体素保存在内存中，供按坐标、索引和区域遍历查询；显示点云不是规划数据源。当前只验证地图及查询，不移植 A*、B 样条优化、规划状态机，不实现洞口识别、穿越约束或控制。

第一版不加入 IMU，不构建 ESDF，不引入 ROS、OctoMap、TSDF 或跨进程通信。使用固定范围地图，限制测试移动范围；不宣称已实现滚动地图或全局一致的稠密重建。手持几何质量必须通过真实移动实验验收，静态运行成功不能代替。

## 2. 方案比较与建议选择

1. 直接复制原 GridMap 并删除 ROS：改动直观，但仍将输入、调度、概率数组、膨胀和显示混在一起，规划读写同步也不明确。
2. 保留 EGO 的概率融合、射线和膨胀思路，整理独立更新核心和只读查询：可逐项对照算法，并给未来规划提供明确契约。采用此方案作为设计建议。
3. 改用其他地图框架：引入新的表示、参数和依赖，当前场景没有证据需要这样做，暂不采用。

同进程已由用户确认；固定网格、精简不可变快照、以下测试默认值及目录命名均为本设计的工程建议，尚不视为用户逐项确认。

## 4. 模块和工程边界

遵循现有工具级 CMake 组织，在 `tools/ego-occupancy/` 下增加独立 CMake 工程，包含公共头文件、核心源码、回放和显示应用；配置放 `config/`，实验说明放 `docs/`。不重排现有工程，不覆盖普通实时、离线和计时基线。最终文件拆分由实现者按最小合理规模决定。

- `OccupancyMapper`：单写者，维护概率、观测标记、射线缓存和膨胀结果，接收不依赖 ORB/RealSense 类型的观测。
- `MapSnapshot` / `MapReader`：不可变体素查询、元数据、批量/区域遍历。核心查询只依赖标准库和 Eigen。
- RGB-D 投影适配层：依赖 OpenCV，把深度和已核实的相机投影模型转换为更新所需射线；RealSense 仅在采集边界，ORB 仅在位姿边界。
- 独立应用：合成输入测试、文件回放、手持实时建图；显示使用已有 Pangolin 能力，不强制引入 PCL。显示与规划调用同一查询数据。

独立库 C++17；支持只构建核心和测试而不安装 ORB、RealSense、Pangolin。复用上游代码时保留作者及许可证声明，记录来源版本；不假设原 ROS/CMake 文件可直接用于新工程。

## 5. 输入和坐标契约

一次 `DepthObservation` 必须包含拥有生命周期的深度图、尺寸、像素编码、转换为米的比例、相机投影信息、捕获索引、彩色/深度时间戳和时间域、应用接收的 steady_clock 时刻，以及同一帧的位姿状态。

位姿数据包含 `T_grid_camera`、参考/子坐标系名称、源会话及地图身份、源坐标修正版本、跟踪有效性。变换采用列向量：`p_grid = T_grid_camera * p_camera`。ORB 边界核实 `TrackRGBD` 返回的 `Tcw`，取逆并组合显式配置的 `T_grid_orb`；输入深度所属相机的光学系必须与该相机变换一致。对齐到彩色的深度使用实际对齐输出的标定，不沿用原始深度内参，也不沿用 EGO 硬编码的 cam2body。

Z16 使用实际 `depth_scale_m_per_unit`；32F 入口明确要求米。图像缩放后必须同步变更投影模型。针孔投影仅适用于已校正输入；若图像有畸变，适配器必须根据实际标定建立经过验证的逐像素射线表或进行正确校正。不支持的投影模型应在预检时报错，不能忽略畸变后继续融合。射线表按光学 Z 深度定义，不能把 Z 当作欧氏距离。

RGB-D only 不提供重力方向保证。第一版地图使用有明确标签的局部 SLAM 坐标系；默认禁用上游地面/虚拟天花板约束，不假设任意 SLAM Z 轴是竖直方向。与未来无人机机体系、重力系的标定另行验收。

输入校验失败、非单调时间、无效位姿、跟踪非 OK、坐标版本未知时不融合并记录原因。空间对齐不代表曝光同步；保留现有同时间域及配对时间差检查。建图不能把最新位姿配给旧深度。

## 6. ORB 接入先决工作

核心与合成测试不等待 ORB 改造；真实多帧 RGB-D 接入必须先满足一致位姿契约。

在独立实验构建中增加一个小型 ORB 桥接记录：由实际跟踪路径在地图更新锁的正确保护范围内复制帧号/时间、是否有位姿、跟踪状态、位姿和地图生命周期标识；发布的是数值副本，不能跨线程传递 ORB Map/MapPoint 裸指针。新地图、重置、地图合并、回环及全局修正路径必须产生可区分的失效事件。事件通知与新观测进入同一个版本控制契约，不能仅靠采样位置突变阈值发现修正。

实现计划首先核实板端检出源码、锁顺序、早返回和后台修正路径，选择最小桥接补丁；不承诺现成 GetMapId/MapChanged API 就足够。尽量使用独立桥接状态和独立核心库，不覆盖已跑通核心；若改变公开类布局，则必须重编全部受影响对象，禁止旧新 ABI 混用。源代码/构建证据应记录到独立目录。

普通局部 BA 也可能改变位姿，不能将每次局部 BA 一律当作地图切换，否则地图会持续清空。第一版目标是短范围局部融合，普通优化造成的重影要实测；新地图及重大坐标修正明确重置。精确区分的钩子和测试必须在实时接入前完成。无法可靠标识的情况拒绝融合并解释，不能悄悄降级到未验证位姿。

离线回放可使用同一桥接 ORB 逐帧生成观测，或使用经过验证、逐帧绑定坐标版本的位姿文件。旧 tracking.csv 不自动获得可信身份。测试程序可以使用明确标注的人工/合成位姿，但不得把这类运行称为真实 SLAM 接入完成。

## 7. 体素存储与分类

固定轴对齐范围；原点、尺寸和分辨率配置化。测试建议范围 `8×8×4 m`，分辨率 `0.05 m`，不是最终穿洞参数。每个新坐标 epoch 的第一份合格观测确定地图中心，原点为其位置减半尺寸，此后不随相机移动。越界查询返回 Outside，不钳制到边界格。

单轴体素数 `ceil(size/resolution)`；实际查询边界由原点和体素数乘分辨率定义，半开区间 `[origin, origin+N*r)`。构造时检查有限正数、乘法溢出、体素数量和内存预算。位置转索引用 floor，体素中心为 `origin + (index+0.5)*resolution`，线性下标采用 EGO 的 X/Y/Z 顺序。负坐标、恰在边界及非有限值有明确测试。

可写核心保存概率 log-odds、是否被可靠观测、膨胀标记和帧内暂存。第一版采用 double 概率以便对照原 EGO，不急于量化压缩；观测标记独立表示，避免把概率下限兼作未知哨兵。有效观测的初始概率为 0.5，按 hit/miss logit 更新并截断。参数建议 `p_hit=0.70, p_miss=0.35, p_min=0.12, p_max=0.97, p_free=0.35, p_occ=0.80`；这些是测试默认，不是已优化参数。

未观测或概率介于 free/occupied 阈值之间为 Unknown；`p<=p_free` 且已观测为 Free；`p>=p_occ` 且已观测为 Occupied。参数校验包含 `0<p_min<=p_free<0.5<p_occ<=p_max<1`、hit/miss 方向。该三态策略是对原接口的显式改进，不声称逐体素行为完全相同。

原 EGO 的 205 万体素基本数组约 29 MiB 是参考下界之外的量级估算；新增观测标记、缓存实现、膨胀、快照、图像及 ORB 内存必须单独计量，不能把此数当整个应用内存上限。分辨率减半会让同体积体素数约增为八倍。

## 8. 射线融合与膨胀

保留 EGO 的逐帧 hit/miss 汇总后更新思想，避免一个体素被同帧大量重复像素无限增强。每帧同体素 hit/miss 采用原 EGO 的多数规则，平票 hit 优先；缓存计数和代数标记使用有明确范围/溢出处理的类型，不照抄 char 帧代数回绕行为。

可靠有效深度：测量端点更新 hit，端点前可见路径更新 miss；端点不同时被同一射线当作 free。零深度、NaN、负值、过近或测量不可靠的像素默认跳过；不得把无法测量视为看到了远处。可靠有效测量超过配置的建图射程时，可以在最大欧氏射程截断，路径更新 miss，截断点不 hit。边界裁剪同样不能制造边界障碍。

在网格坐标 `(p-origin)/resolution` 中执行三维 DDA，并对轴平行、同格、零长度、负坐标和边界裁剪做几何测试。直接迁移原代码时要核实连续射线方向和原点偏移，不能仅因复用了文件就假设遍历正确。可配置最小更新距离保护相机附近区域。无效观测不会清空旧障碍；只有后续可靠 miss 证据才能降低其占据概率。

第一版使用可配置的逐轴膨胀距离，按 `ceil(radius_axis/resolution)` 生成轴对齐膨胀盒，初始可各轴相同。明确这与原 EGO 深度路径的立方邻域思想相同，实际有效半径经过体素量化，不是精确球形模型。无人机外廓/误差未知时仅给测试参数，不能宣称具有飞行净空保证。

先采用全图重建膨胀标记以确保障碍撤销没有残留，测量板端开销后再决定局部更新；有限地图可从占据格列表加速，但任何优化必须保持等价。快照只在原始分类和膨胀都完成后发布，不能发布中间状态。显示同时支持原始占据、膨胀与指定切片的未知/空闲，便于识别洞口被膨胀封闭或缺乏观测的问题。

## 9. 同进程查询和快照契约

`OccupancyMapper` 由一个建图线程独占。`MapSnapshot` 保存每体素 raw state（1 字节）、inflated flag（1 字节）以及元数据，不复制射线缓存和概率历史。规划/显示使用 `shared_ptr<const MapSnapshot>` 持有生命周期，发布后数组不再修改。C++17 采用 shared_ptr 的原子装载/存储或等价短互斥实现；不声称这些操作必然 lock-free。

查询包含按世界位置/体素索引返回 `VoxelQuery{state,inflated}`、`isBlocked(position, UnknownPolicy)`、分辨率、原点、尺寸、位置/索引转换，以及只读区域遍历。查询 O(1)，不暴露可写数组。Outside 与非有限位置对阻塞查询恒为 true；Occupied 或 inflated 为 true；Unknown 由显式策略决定，默认阻塞。Free 且未膨胀才可通行。没有有效快照时获取失败，不回退为空地图。

元数据包含 schema version、源会话/坐标身份及修正版本、occupancy epoch、融合序号、最后融合的传感器时间、应用接收 steady_clock 时刻、发布时刻、投影/配置身份。时间新鲜度从最后已融合观测的接收时刻算，不以发布时刻掩盖旧输入。颜色/深度的传感器时间不直接与 host steady_clock 相减。

建议提供 `MapReader::acquire()` 和 `MapReader::isUsable(snapshot, now)`。一次未来规划始终用同一快照。地图失效事件通过独立、线程安全的 epoch/status 控制立即更新；旧快照本身仍可读取以保证内存安全，但新计算/结果提交必须再检查当前 epoch 和状态。不通过修改 const 快照假装撤销它。普通新融合序号不使正在使用的旧快照自动失效；未来规划结果仍须在当时最新有效地图上进行碰撞复核。

后续 `EgoGridMapAdapter` 绑定一份快照，提供 `getResolution()`、`getInflateOccupancy()` 等实际调用接口；阻塞结果明确映射到 EGO 的布尔/整数语义，Unknown 的默认语义与上游不同需要记录。第一版仅实现查询适配和调用测试，不链接完整优化器。

## 10. 有界线程、生命周期与失效处理

复用原采集、TrackRGBD、录制链路；新增独立建图工作线程，观测队列容量建议 2，满时整包丢最旧，保持帧/位姿绑定。显示在其图形上下文所属线程低频读取快照；未来规划另有自己的线程。队列锁内不做 SLAM、射线、显示或文件 I/O。不移动现有录制写盘到建图线程。

快照使用最多 3 个预分配数据槽，通过共享所有权保证读者持有时不回写。如果没有空闲槽，跳过快照发布并计数，不无限分配或等待读者；可写融合继续并反映在下次发布结果。元数据控制和失效通知不依赖拿到快照槽，不能因慢读者延迟失效。约 205 万体素、两字节查询数据、3 槽约 11.7 MiB，另有元数据与管理开销。规划/显示不得跨无关工作长期保留多份历史快照。

建图最多处理配置频率下最新观测，初始测试目标 10 Hz，显示建议 5 Hz；均可调且不保证 RK 实测达标。融合不得排队积累秒级历史。默认可用性超时建议 0.5 s，仅作测试参数。记录观测队列/快照发布跳过、更新/膨胀/发布耗时、最后融合年龄和 RSS；其分位统计在实验后产生。

失效事件、跟踪丢失、输入源停止、致命错误立即将 reader 状态设为不可用于规划。普通旧帧丢弃不构成坐标重置。新地图/重置/重大坐标修正或跟踪中断后恢复：递增 occupancy epoch，清空概率、标记及暂存，拒绝旧 epoch 队列观测；第一份新合格观测建立新原点后恢复发布。不要将“暂停融合”误实现为“旧地图永久有效”。

源停止时可保留最终快照用于显示/导出，但 live status 标记不可用于实时规划。离线 final snapshot 也标注 replay/finalized，不伪装为新鲜实时数据。退出时停止生产、关闭/唤醒有界队列、结束并 join 自有建图线程，确保没有悬空图像或快照写入；既有 ORB 后端退出风险保留独立说明，不借本改动宣称其已修复。

## 11. 验证和可重复输出

先验证核心：射线端点/轴平行/斜线/负坐标/地图边界、同帧计数、hit/miss 饱和和三态阈值、无效深度不清障、有效背景 miss 可撤销障碍、膨胀撤销及边界。合成带已知开口的几何输入验证原始开口与膨胀开口，不能只对着实现写镜像断言。

并发契约验证：读者持有快照时连续更新不改变其内容；3 槽耗尽时内存不增长且发布跳过；reset/失效不被慢读者阻塞；旧 epoch 输入与结果被拒绝；暂停/结束时 stale 状态正确。用一个不含规划算法的小程序逐点/逐索引查询，证明体素接口可用，并核对 EGO adapter 的未知/边界阻塞语义。

离线验证：使用已验证位姿或同一 ORB 桥接得到的绑定观测，保留输入配置、源版本、融合参数、观测顺序和地图结果摘要。同一组绑定观测的核心重放应得到一致结果；重新运行异步 ORB 的结果另行比较，不承诺其位姿逐位确定。可导出 occupied/inflated PLY 用于检查，不能只导出 occupied 点然后声称保存了完整三态地图。

提供带版本和元数据的完整查询网格快照保存/加载，包含所有体素的状态和膨胀标记；它用于离线查询/显示，不保存可写概率和暂存历史，不支持从此文件无损续接融合。实现者可选择简单二进制容器，必须检查尺寸、长度、版本和配置，并验证往返查询一致。大产物放忽略的数据目录。

实时手持验证顺序：静止看已知尺寸开口；缓慢平移/旋转看边框重影；多视角补充洞口及背景可见区域；失踪/恢复及新地图测试；RK3576 上记录更新耗时、端到端数据年龄、内存、队列与状态。量化原始/膨胀洞口尺寸和重复观测偏差；没有洞口尺寸与无人机外廓前，不凭视觉截图给出可飞行结论。

## 12. 分阶段实施和完成标准

1. 核心库、合成几何、快照、EGO 查询适配和必要测试；不依赖硬件即可构建运行。
2. 核实并实现独立 ORB 一致位姿桥接，完成身份/修正/失效测试；接入已有录制数据，提供离线显示、查询和网格快照往返。
3. 独立实时入口接 D435i + ORB，保留已有运行基线；先宿主验证，再核实板端依赖并 ARM64 构建/短测，最后用户参与手持开口实验。

本阶段完成意味着：无 ROS 连续 RGB-D 占据更新可在 RK3576 上运行，几何和资源指标有实测，完整内部体素可被独立 C++ 查询者一致读取，保存/加载后查询相同，并明确标记未知、过期、失效和重置。地图显示成功不等于无人机穿洞规划或飞行验收完成。

尚需后续实测/用户提供的参数：洞口最小净空、含桨叶外廓、定位和深度误差预算、目标飞行速度。它们决定最终分辨率/膨胀/更新率/超时，不阻塞可配置核心与合成验证。自动洞口定位与穿越目标约束在规划阶段单独设计。
